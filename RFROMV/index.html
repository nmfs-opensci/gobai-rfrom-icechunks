RFROM: Random Forest Regression Ocean Maps

About RFROM

John M. Lyman and Gregory C. Johnson

RFROM is a collection of Random Forest Regression Ocean Maps. These maps are computed from random forests constructed in different ocean basins. The maps are trained on ocean profiles of temperature and salinity measurements from the surface to 2000 m. RFROM uses satellite sea surface height (SSH), satellite sea surface temperature (SST), time, latitude, and longitude as predictors for temperature maps and ocean heat content maps. It adds the temperature maps as an additional predictor for salinity maps. The results are near-global ¼-degree x ¼-degree x 7-day resolution maps of temperature and salinity on 58 different depth layers, along with ocean heat content anomaly on 10 different layers.

The temperature and salinity profile data come from the UK Met Office Hadley Centre (EN.4.2.2) and the Argo Program, SSH delayed-mode maps from the Copernicus Marine Environment Monitoring Service (SEALEVEL_GLO_PHY_L4_MY_008_047) and SST maps from NOAA (OISST V2.1). Real time maps use real time SSH (SEALEVEL_GLO_PHY_L4_NRT_008_046) where delayed mode SSH is not available.

RFROM is described in the papers below:

Lyman, J. M. and G. C. Johnson, 2023: Global High-Resolution Random Forest Regression Maps of Ocean Heat Content Anomalies Using in Situ and Satellite Data. J. Atmos. Oceanic Tech., DOI: 10.1175/JTECH-D-22-0058.1.

Lyman, J. M. and G. C. Johnson. 2026. High Resolution Random Forest Regression Ocean Maps (RFROM) of Temperature and Salinity, Submitted Journal of Geophysical Research – Machine Learning and Computation.

RFROM V2.2 follows the original methodology described in the paper above, with the following improvements.

  1. SST is only used as a predictor in the upper 200 m, where it is important.
  2. To reduce spatial artifacts, four random forest models are made for each depth level. These models use 5° x 5° degree tiles instead of exact latitudes and longitudes as prediction variables. In a given tile longitudes and latitudes of profile positiions have been rounded to the center values of the tile. The center of the tiles in each of the four models differ so that the tiles are offset from one another and there is only 25% area overlap between any two models. When constructing the final maps, a weighted average of all four models is used. The weights are set by the distance to the center of a tile to point where the final map for that point is estimated.
  3. The all-year model for a region was used for years after 2006 if data coverage was low for that year in the region being mapped.
  4. The Sulu and Celebes Seas are now separate basins.

RFROM V2.3 methods are described in Lyman and Johnson (2026).

RFROM V2.3 in the cloud (NOAA Open Data Dissemination)

V2.3 is published in the public Google Cloud Storage bucket gs://noaa-oar-rfrom. It is open data: no account, no credentials, no request quota. There are two ways in.

WhatWhereUse it for
Icechunk storegs://noaa-oar-rfrom/icechunk/v2.3 The whole record — all four variables on one 1719-week time axis, opened as a single dataset. Python only.
netCDF filesgs://noaa-oar-rfrom/netcdf/v2.3/ Ordinary netCDF-4 files, 18 per variable. Any language. Stream them or download them.

The Icechunk store holds no copy of the data — it is metadata pointing into the same netCDF files, so both routes return identical values.

Python — install

pip install xarray gcsfs h5netcdf     # netCDF files
pip install icechunk zarr             # ...plus the Icechunk store

Python — the whole dataset, via Icechunk

import icechunk as ic, xarray as xr

SRC = "gs://noaa-oar-rfrom/netcdf/v2.3/"
repo = ic.Repository.open(
    ic.gcs_storage(bucket="noaa-oar-rfrom", prefix="icechunk/v2.3", anonymous=True),
    authorize_virtual_chunk_access=ic.containers_credentials({SRC: ic.gcs_credentials(anonymous=True)}),
)
ds = xr.open_zarr(repo.readonly_session("main").store, consolidated=False, chunks={})

Both halves need configuring: the store is read from the bucket, and the data it points at is read from the netCDF files. That is what the authorize_virtual_chunk_access line does — without it you get metadata and no data. ds then holds ocean_temperature, ocean_salinity, ocean_temperature_error, ocean_salinity_error, 1993-01-01 to 2025-12-05 weekly, plus a data_mode flag (0 = settled, 1 = provisional real-time). If reads feel slow, raise Zarr's default concurrency of 10: import zarr; zarr.config.set({"async.concurrency": 128}).

Python — a single netCDF file

import xarray as xr

url = "gs://noaa-oar-rfrom/netcdf/v2.3/temp/RFROMV23_TEMP_STABLE_1993-01-01_1994-11-25.nc"
ds = xr.open_dataset(url, engine="h5netcdf", storage_options={"token": "anon"}, chunks={})

To see what is published: import gcsfs; gcsfs.GCSFileSystem(token="anon").ls("noaa-oar-rfrom/netcdf/v2.3/temp"). Streams are temp, sal, temp_error, sal_error. Note that file names sort lexically rather than chronologically, so use the Icechunk store if you want the record in time order without thinking about it.

R

R can read these files without downloading them. Append #mode=bytes to the HTTPS URL and netCDF reads only the bytes it needs.

install.packages("ncdf4")
library(ncdf4)

u <- paste0("https://storage.googleapis.com/noaa-oar-rfrom/netcdf/v2.3/temp/",
            "RFROMV23_TEMP_STABLE_1993-01-01_1994-11-25.nc#mode=bytes")
nc <- nc_open(u)

# one horizontal slice: 4x4 points, first pressure level, first time step
x <- ncvar_get(nc, "ocean_temperature", start = c(600, 300, 1, 1), count = c(4, 4, 1, 1))
nc_close(nc)

Dimensions are reversed relative to Python: (longitude, latitude, mean_pressure, time). RNetCDF::open.nc() works the same way.

Streaming needs a netCDF library built with byte-range support. Most are; to check yours, run the code above — if it fails with a message about an unknown file format or an inaccessible DAP response, yours is not, and you should download the file first:

u <- paste0("https://storage.googleapis.com/noaa-oar-rfrom/netcdf/v2.3/temp/",
            "RFROMV23_TEMP_STABLE_1993-01-01_1994-11-25.nc")
download.file(u, "rfrom.nc", mode = "wb")   # ~7.5 GB
nc <- nc_open("rfrom.nc")

Files run from about 2.7 to 9.2 GB each, so downloading is worth avoiding where you can.
